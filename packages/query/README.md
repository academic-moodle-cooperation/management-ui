# @oc-mui/query

Data-fetching layer. Wraps TanStack Query and `graphql-request` behind a single workspace import, exposes typed GraphQL hooks generated from `.graphql` files, and owns the `definePluginConfig` reader API.

**Contract**: Config Contract 1.0 (frozen for 1.x) — see [`docs/architecture/CONFIGURATION.md`](../../docs/architecture/CONFIGURATION.md). Public API surface tracked in [`etc/query.api.md`](./etc/query.api.md).

## The wrapper rule

This package is the **only place in the workspace allowed to import from `@tanstack/react-query`**. Apps, plugins, and other packages must import `useQuery`, `useMutation`, `QueryClient`, … from here. The rule is enforced by `no-restricted-imports` in `@oc-mui/eslint-config` with an explicit exception for this directory.

If we ever need to swap or major-bump the underlying library, we change it here without touching plugins or apps.

## Usage

### Read your plugin's config slice

```ts
import { z } from "zod";
import { definePluginConfig } from "@oc-mui/query";

const schema = z.object({
  pageSize: z.number().int().positive().default(20),
});

export const myPluginConfig = definePluginConfig({
  id: "my-plugin",
  schema,
  defaults: { pageSize: 20 },
});

// In a component:
const { pageSize } = myPluginConfig.use();

// In an event handler:
const { pageSize } = myPluginConfig.read();
```

### Run a typed GraphQL query

```ts
import { useGetMyEventsQuery } from "@oc-mui/query";

const { data, isLoading } = useGetMyEventsQuery({ limit: 20 });
const events = (data?.currentUser?.myEvents?.nodes ?? [])
  .filter((e): e is NonNullable<typeof e> => e !== null);
```

## Surface

| Symbol | Purpose |
|--------|---------|
| `QueryProvider` | Wraps the app in a TanStack `QueryClientProvider`. The shell mounts it; plugins consume the client through hooks. |
| `definePluginConfig({ id, schema, defaults })` | Builds a typed config reader. Returns `{ id, schema, defaults, register, use, read }`. Reading another plugin's slice is forbidden — lint catches it. |
| `useAppConfig()` | Reads the merged `AppConfig`. Source of truth for `app.theme`, `app.locale`, `app.enabledPlugins`. |
| `useUserInfo()` | Currently-signed-in user. |
| Generated hooks (`useGetMyEventsQuery`, …) | One hook per `.graphql` operation, regenerated by GraphQL Codegen into [`src/gql-generated.ts`](./src/gql-generated.ts). |
| `EVENT_SORTABLE_FIELDS`, `SERIES_SORTABLE_FIELDS` | Runtime lists of the fields the backend accepts in `EventOrderByInput` / `SeriesOrderByInput`. Derived from the schema by codegen (see below); fed into `restrictSortingToFields` from `@oc-mui/ui` so tables only offer sorts the backend supports. |
| `gql` (re-export from `graphql-request`) | For ad-hoc operations; prefer codegen for anything reused. |

For the exhaustive list, see [`etc/query.api.md`](./etc/query.api.md).

## Code generation

Two source files in this package are **generated from the live GraphQL schema** and committed to the repo, so the rest of the workspace (and CI) builds without a backend:

| Generated file | Produced by | Contains |
|----------------|-------------|----------|
| [`src/gql-generated.ts`](./src/gql-generated.ts) | `@graphql-codegen` `typescript` + `typescript-operations` + `typescript-react-query` plugins | Types and React Query hooks for every `.graphql` operation. |
| [`src/schema-input-fields.generated.ts`](./src/schema-input-fields.generated.ts) | the local [`codegen-plugins/input-field-names.mjs`](./src/codegen-plugins/input-field-names.mjs) plugin | Runtime `as const` arrays of the field names in each `*OrderByInput` / `*FilterByInput` type. TypeScript input types are erased at runtime, so this is how the UI knows which fields are orderable/filterable without hardcoding them. |

**You only need to run codegen when the GraphQL schema changes** — not as part of normal setup or per-build. The generated files are committed; a fresh clone builds fine without ever running codegen.

When the schema does change:

```bash
# Point at a backend exposing the schema (defaults to http://127.0.0.1:8080/graphql).
GRAPHQL_ENDPOINT=https://your-opencast/graphql \
  pnpm --filter @oc-mui/query codegen
```

This rewrites both generated files. Commit the diff. If `schema-input-fields.generated.ts` changes, `src/sortableFields.test.ts` may need its pinned expectations updated — that test failing is the intended signal that the set of sortable/filterable fields shifted.

The config lives in [`src/codegen.ts`](./src/codegen.ts); it reads `GRAPHQL_ENDPOINT` and optional `GRAPHQL_HEADERS` (JSON) from the environment.

## Layer

Integration. Depends on `@oc-mui/plugin-system`, `@oc-mui/utils`. The Config Contract reader (`definePluginConfig`) ties it to `@oc-mui/ui-config` for the `AppConfig` shape.
