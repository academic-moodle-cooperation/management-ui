# shadcn/ui components — mostly generated, edit with care

This folder holds the **shadcn/ui atomic components** (Radix UI + Tailwind CSS, copied into the repo rather than installed as a dependency). Most `.tsx` files here were generated by the shadcn CLI, but **not all of them are pristine CLI output**:

- [`index.tsx`](./index.tsx) is a **hand-written barrel** that re-exports every component (plus `toast` from `sonner`, the `use-mobile` hook, and `DefaultLandingPage`). The CLI does not manage it — keep it updated by hand when adding components.
- [`sidebar.tsx`](./sidebar.tsx) is **hand-modified** (it imports `@oc-mui/i18n`, among other changes). A blind `npx shadcn@latest add sidebar` would clobber those changes.

So: prefer regenerating through the CLI for untouched components, but diff-review any file the CLI rewrites before committing.

## Configuration

The shadcn configuration is `packages/ui/components.json` — **manually maintained**, not generated. It defines the style (`new-york`/`default`), Tailwind settings, and the import aliases:

| Alias | Path | Generated? |
|-------|------|------------|
| `ui` | `@oc-mui/ui/components/ui` | Yes (this folder — with the exceptions above) |
| `utils` | `@oc-mui/ui/lib/utils` | No — contains `cn()` |
| `hooks` | `@oc-mui/ui/hooks` | No |
| `lib` | `@oc-mui/ui/lib` | No |
| `components` | `@oc-mui/ui/components` | No — parent folder with hand-written composed components |

## Adding a component

```bash
cd packages/ui
npx shadcn@latest add [component-name]
```

Then add the export to [`index.tsx`](./index.tsx).

## Customizing a component

1. **Preferred**: copy it to another location (e.g. `packages/ui/src/components/`) and modify the copy.
2. Fork it in place (like `sidebar.tsx`) — accepted, but the change is silently lost if someone re-runs the CLI for that component, so leave a marker comment.

## TypeScript

This folder is type-checked, but errors originating from generated files are tolerated: consumer packages rely on `skipLibCheck`, and apps/plugins exclude this folder in their `tsconfig.json` where possible.
