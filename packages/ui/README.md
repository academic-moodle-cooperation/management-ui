# @oc-mui/ui

Shared component library built on Tailwind CSS v4 and Radix UI primitives (via shadcn/ui). Atomic components (Button, Card, Input, …) plus composed building blocks (app shell, datatable, metadata fields, ACL editor, date picker).

This is the only place plugins should source UI components — the Theme Contract guarantees consistent styling, and bundling your own shadcn copies breaks org theming.

## Usage

```tsx
import { Button, Card, CardContent } from "@oc-mui/ui/components";
import { cn } from "@oc-mui/ui/lib/utils";
import { Home, Video } from "@oc-mui/ui/components/icons";

<Card className={cn("bg-card", className)}>
  <CardContent>
    <Button>Save</Button>
  </CardContent>
</Card>;
```

Plugin authors import from the **subpath exports** — never the package root — to keep the bundle tree-shakeable:

| Subpath | What it provides |
|---------|------------------|
| `@oc-mui/ui/components` | Atomic + composed components (Button, Card, Table, DataTable, AppShell, …). |
| `@oc-mui/ui/components/icons` | `lucide-react` icons re-exported with a stable surface (Home, Video, ExternalLink, …). |
| `@oc-mui/ui/lib` | Utility helpers (`resolveFirstAssetUrl`, …). |
| `@oc-mui/ui/lib/utils` | The `cn()` class-merging helper. |
| `@oc-mui/ui/hooks` | `useMobile`, `useClickOutside`, … |
| `@oc-mui/ui/styles`, `@oc-mui/ui/globals.css` | The semantic-token CSS. Imported once by the shell. |
| `@oc-mui/ui/config-primitives` | Building blocks for plugin config UIs. |
| `@oc-mui/ui/postcss.config` | Shared PostCSS config — an app's `vite.config.ts` pulls it in. |

## Components

The library is split between **atomic shadcn components** (under `src/components/ui/`) and **composed components** (everything else under `src/components/`). The atomic ones are generated by `npx shadcn@latest add`; the composed ones are hand-written and depend on them.

| Composed component | What it does |
|--------------------|--------------|
| `AppShell` | The shell's layout — sidebar, header, footer, main content area. The host mounts this once; plugin extension points fill the slots. |
| `DataTable` / `MuiTable` | Sortable, filterable, paginated tables — the canonical way to render lists. |
| `MetadataField`, `MetadataUpdateField` | Form controls for Opencast metadata. |
| `AclEditor` | Access-control-list editor. |
| `DatePicker`, `DateTimePicker` | Calendar input. |
| `InfiniteScroll` | Sentinel-driven incremental loading. |
| `Container`, `AppHeading`, `OverflowTooltip`, `DebouncedInput` | General-purpose layout/UX. |

## Theme

Components consume the semantic tokens from [`src/styles/globals.css`](./src/styles/globals.css). Org themes override the token values, not the class names. Full contract: [`docs/plugins/styling.md`](../../docs/plugins/styling.md).

## Layer

Integration. Depends on `@oc-mui/utils`, `@oc-mui/plugin-system` (for components that integrate with extension points), `@oc-mui/router` (for components that render links).
