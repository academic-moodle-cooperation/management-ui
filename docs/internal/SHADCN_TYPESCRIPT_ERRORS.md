# shadcn/ui TypeScript Errors

## Problem

The `packages/ui/src/components/ui/` folder contains **auto-generated shadcn/ui components**. These files are generated by the shadcn CLI and may not always conform to our strict TypeScript settings:

- `verbatimModuleSyntax: true`
- `exactOptionalPropertyTypes: true`

This can cause TypeScript errors (TS1484, TS2375) in:

- `@workspace/ui` package itself
- Packages that import from `@workspace/ui` (e.g., `@workspace/plugins`, `plugin-core`, `@workspace/app-runtime`)

## Solution

**These errors are acceptable and should be ignored** because:

1. **Auto-generated files**: The shadcn CLI overwrites these files, so manual fixes would be lost
2. **External source**: We don't control the code generation
3. **Functionality**: The components work correctly despite the type errors

## For CI/Contributions

When running `pnpm check-types` as a contribution requirement:

- ✅ **Acceptable**: TypeScript errors from `packages/ui/src/components/ui/**` in:
  - `@workspace/ui`
  - `@workspace/plugins`
  - `plugin-core`
  - `@workspace/app-runtime`
- ❌ **Not acceptable**: TypeScript errors in manually written code

### CI Configuration

For CI/Contributions, you have two options:

**Option 1 (Recommended)**: Accept that `@workspace/ui` and `@workspace/plugins` may have shadcn-related errors. Only fail CI if there are errors in manually written code:

```yaml
# .github/workflows/test.yml
- name: Check types
  run: |
    pnpm check-types 2>&1 | grep -v "packages/ui/src/components/ui" | grep -v "src/components/ui" || true
    # Then manually check if there are real errors
```

**Option 2**: Exclude packages with shadcn errors from the check-types requirement in CI:

```yaml
- name: Check types (excluding shadcn packages)
  run: pnpm --filter='!@workspace/ui' --filter='!@workspace/plugins' --filter='!plugin-core' --filter='!@workspace/app-runtime' check-types
```

## Consumer Packages

Consumer packages (apps, other plugins) should use:

- `skipLibCheck: true` in their `tsconfig.json` (already configured)
- `exclude` for shadcn files where possible (already configured)

This prevents shadcn errors from propagating to consumer code.
